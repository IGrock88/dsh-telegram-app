# dsh-telegram-app

Мост DeepSeek Harness ⇄ Telegram: **слой 1 — чат** (работает сразу, без публичного
адреса), **слой 2 — панель Mini App** (написана, но выключена до выбора транспорта).

**Статус: работает и зафиксировано владельцем 2026-10-14.** Плагин установлен в профиль
`web`, бот привязан к чату, проверено на телефоне: привязка по контрольному токену, меню с
кнопками, воркспейсы и сессии с названиями, отправка промптов, `/last` с полным текстом
ответа, уведомления о завершении хода, аппрувы кнопками. Тесты — **190/190**, все офлайн.

Главное свойство: в базовом режиме плагину не нужны ни домен, ни nginx, ни туннель,
ни единый открытый порт. Бот общается с Telegram исходящими запросами, а ты — с ботом
в чате.

**Источник истины по поведению — [`SPEC-layer1.md`](SPEC-layer1.md):** тексты экранов,
схема callback-данных, фильтры списков, формат `state.json`, критерии приёмки.
История отладки на живой машине и пять систематических уроков — в
[`HANDOFF.md`](HANDOFF.md).

**Перезапуск сервера — только вам, из своего окна:**

```
powershell -ExecutionPolicy Bypass -File W:\harness\dsh-telegram-app\restart-server.ps1
```

Агент живёт внутри того же `dsh web`, поэтому перезапуск «через агента» убивает сам агент
посреди команды, и лог не записывается. Однажды это стоило трёх потерянных прогонов.

## 1. Модель: два слоя

| | **Слой 1 — чат** (готов) | **Слой 2 — панель Mini App** (выключена) |
| --- | --- | --- |
| Что даёт | привязка по контрольному токену, навигация «меню → воркспейсы → чаты → работа с чатом», задача обычным текстом, стоп, approvals кнопками, уведомления | веб-панель в Telegram: список чатов, история, живой лог, создание сессии |
| Что нужно от тебя | токен BotFather (контрольный токен генерируется сам) | **плюс** публичный HTTPS-адрес (§5) |
| Публичный адрес | не нужен вообще | обязателен: Telegram открывает `web_app` только по `https` с валидным сертификатом |
| Открытые порты | ни одного | ни одного на стороне Windows, если использовать туннель |

```
Слой 1 (ничего снаружи не нужно):

   DSH (Windows)  ──исходящий HTTPS──►  api.telegram.org  ◄── телефон (чат с ботом)
        │
        └── та же машина, порт 3080 наружу не выставлен

Слой 2 (нужен транспорт до 127.0.0.1:3080, потому что порт слушает только loopback):

   телефон ──https──► [ 2а: твой nginx + труба │ 2б: edge Cloudflare + cloudflared ]
                                        │
                                        ▼
                                 127.0.0.1:3080  ← DSH: и страница, и API
```

Сервер-посредник в слое 2 — это **только транспорт**. Страницу и все данные отдаёт твой
DSH; пока панель открыта, трафик идёт через посредника постоянно. Telegram к твоему
домену **не ходит**: вебхук не используется, бот сам опрашивает Bot API.

## 2. Навигация в чате

```
L0  МЕНЮ                    /start, /menu, reply-кнопка «🏠 Меню»
    [📁 Воркспейсы] [⚙️ Настройки]
        │
        ▼
L1  ВОРКСПЕЙСЫ              только папки, где есть подходящие сессии;
    dsh-telegram-app · 3 сессии · 2 ч назад      порядок — как в сайдбаре UI
        │
        ▼
L2  ПОСЛЕДНИЕ N ЧАТОВ       N — настройка чата, по умолчанию 5
    1. 🟢 📌 Фикс авторизации · 12 мин
        │
        ▼
L3  РАБОТА С ЧАТОМ          любой текст уходит промптом в эту сессию
    последний ответ: «…до 200 символов…»

S   НАСТРОЙКИ               лимит чатов в папке, порядок папок, уведомления;
                            значения хранятся **на чат**, тап применяется сразу
```

Каждый экран — **одно сообщение**, которое редактируется: переходы не засоряют чат.
На L1–L3 есть `[⬅️]`, `[⚙️]` и `[🏠 Меню]`. Привязка сессии живёт, пока ты не выберешь
другую: текст, отправленный не с L3, всё равно уходит в привязанную сессию, и бот
называет её в ответе («→ отправлено в «Фикс авторизации»»).

В списки не попадают субагенты, пустышки и архивные сессии. Ответ агента автоматически
не пересылается — он доступен по `📄 Последние 5` и `/last`.

## 3. Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/menu` | открыть L0 (непривязанному чату — сначала попросит токен) |
| `/chats`, `/chats <n>` | L1; с номером — сразу L2 для n-й папки |
| `/use <n\|id>` | привязать сессию и показать L3 |
| `/new [путь]` | создать сессию (каталог: аргумент → папка привязки → `cwd` → первая папка) |
| `/last [n]` | последние n сообщений (по умолчанию 5, максимум 10) |
| `/stop` | отменить текущий ход |
| `/status` | чат, привязка, сессия, счётчики, версии |
| `/settings` | открыть экран S |
| `/notify on\|off`, `/limit <3\|5\|10\|15>`, `/sort registry\|activity` | то же, что тапы на S |
| `/unbind` | отвязать сессию (саму сессию не трогает) |
| `/unpair` | снять авторизацию чата, с подтверждением кнопкой |
| `/whoami` | `user id`, `chat id`, статус — **отвечает и без авторизации**, throttled |
| `/help` | справка |

Пустой текст — игнор; длиннее 8000 символов — отказ (файлы слой 1 не принимает).

## 4. Настройка (два секрета, без правки YAML)

Цель: поставил плагин → в DSH открыл раздел **Plugins** (третий пункт в левом сайдбаре,
над *Workspaces*) → нашёл `telegram-app` → вписал токен бота → готово.

> **Не в модалке `Settings`.** Там только General, Models, *Built-in plugins* (встроенные
> плагины самого DSH), Agent presets и Web Search — установленных пакетов в ней нет.
> Форма строки плагина живёт в разделе **Plugins**; её ключ — `<имя пакета>#<id строки>`,
> то есть `dsh-telegram-app#telegram-app`.

### Почему для формы нужна клиентская половина

Схемы `Config` **недостаточно**. Слот `plugins.row.config`, из которого страница Plugins
рисует форму строки, только объявлен — заполняет его клиентская половина самого плагина.
У всех встроенных карточек (`agent-loop`, `shell`, `subagent`, `web-search`) она есть; без
неё плагин работает, схема лежит на хосте, а кнопки настройки в UI нет.

Поэтому у плагина есть [`lib/client.js`](lib/client.js) и объявление в манифесте:

```json
"dsh": { "client": { "platform": "web", "inject": [
  "@deepseek-ai/dsh-client-locale",
  "@deepseek-ai/dsh-client-ui-slots",
  "@deepseek-ai/dsh-client-ui-settings",
  "@deepseek-ai/dsh-client-ui-plugin-manager" ] } }
```

Файл написан на диалекте загрузчика клиентских модулей (`window.__ModuleLoader__.load`),
а не как ES-модуль, и заполняет слот под ключом `dsh-telegram-app#telegram-app`. Владелец
слота передаёт компоненту `view` и готовый `form`; запись идёт через
`form.mutate(ops, revision)`, причём только по тем полям, которые правил пользователь, —
иначе одно сохранение затирало бы соседнее значение.

### И ещё одно: поля должны быть `.volatile()`

Даже с клиентской половиной namespace настроек не появится, если в схеме нет **ни одного**
поля, помеченного `.volatile()`. Хост собирает список настроек через `volatileForm`,
который оставляет только такие поля и **выбрасывает строку целиком**, если не подошло ни
одно:

```js
const form = volatileForm(schema)
if (form === void 0) return []     // строки нет в настройках — форме нечего показывать
```

Поэтому `.volatile()` выставлен на всех полях, которые плагин перечитывает на лету
(`botToken`, `controlToken`, `notifyOnIdle`, дефолты экрана S, таймауты), и **не**
выставлен на читаемые один раз при монтировании (`appPath`, `apiBase`, `proxy`,
`statePath`) — иначе форма обещала бы «живое» применение, которого нет.

| Поле | Смысл |
| --- | --- |
| `botToken` | токен от @BotFather. Помечен `.role('secret')` — форма рендерит его «только на запись» |
| `controlToken` | секрет, который ты один раз отправишь боту в чат. **Генерируется автоматически при первом запуске** и показывается в форме настроек |
| `publicBaseUrl` | **необязательно**; заполняется только если включаешь слой 2. Без него маршрут `/tg-app` не регистрируется вообще |
| `sessionLimitDefault` / `workspaceSortDefault` / `notifyDefault` | дефолты для чатов, которые не открывали экран S |
| `notifyOnIdle`, `notifyMinRunSeconds` | уведомления о завершении хода |
| `approvalMode` | `ask` / `notify` / `off` |
| `cwd` | рабочий каталог новых сессий (необязательно) |
| `statePath` | файл состояния; по умолчанию `<DSH_HOME>/telegram-app/state.json` |

Приоритет значений: **настройка чата → значение из настроек плагина → встроенное**.

### Как живёт контрольный токен

При первом запуске плагин **сам выдаёт** токен и записывает его в свою запись настроек через
`settings.mutate` (именно `mutate`, а не `replace`, — чтобы не стереть секреты, которых форма
не возвращала). Ты открываешь форму, копируешь значение из поля **Control token** и
отправляешь боту одним сообщением в чат. Смена токена не сбрасывает привязки уже
авторизованных чатов.

Две детали, из-за которых это работает именно так, и обе стоили отладки на живой машине:

1. **На диск попадает только SHA-256, и порядок важен.** Плагин публикует значение
   *сначала* и записывает дайджест только для токена, который можно прочитать. Иначе
   получается «заряженный, но не предъявляемый» токен: бот требует секрет, которого никто
   не знает, а восстановить его из хеша нельзя. Поэтому если в `state.json` лежит дайджест,
   а показывать нечего, плагин **выдаёт новый** токен, а не считает себя настроенным.
2. **Публикация ждёт активации плагина.** Хост отдаёт настройки только тем строкам, чей
   файбер в состоянии `ACTIVE`, а `apply()` выполняется во время `LOADING`. Поэтому запись
   откладывается до события активации; иначе она падала бы с `No configurable plugin entry`.

Резервный путь, если формы нет: переменные окружения `DSH_TG_BOT_TOKEN`,
`DSH_TG_CONTROL_TOKEN`, `DSH_TG_PUBLIC_URL`, `DSH_TG_STATE_PATH` или патч профиля
(`~/.dsh/profiles/<profile>/cordis.patch.yml`). Помни, что патч **заменяет** `config`
целиком, а не сливает, — перечисляй в нём все нужные поля.

### Одна зависимость

`@deepseek-ai/schemastery` — то, из чего строится форма настроек. Она объявлена и как
`dependencies`, и как необязательный `peerDependencies`, и **установлена в самом
плагине**: при установке через `dsh plugin add link:<путь>` Node разрешает импорт от
реального пути пакета, а не из `node_modules` профиля, поэтому без локальной установки
форма не собралась бы. Восстановить: `pnpm install --prod`.

Проверку совместимости DSH эта зависимость не затрагивает: `evaluatePluginCompatibility`
смотрит только имена `@deepseek-ai/dsh` и `@deepseek-ai/dsh-*`.

## 5. Слой 2 — панель Mini App (выключена)

Панель написана (страница, JSON API, проверка `initData`, стрим, экран входа) и лежит в
`web/` и [`lib/routes.mjs`](lib/routes.mjs), но маршрут регистрируется **только при
заданном `publicBaseUrl`**. Причина: Telegram открывает `web_app`-страницу только по
`https` с валидным сертификатом, а порт 3080 слушает `127.0.0.1`. Значит, нужен ровно
один источник HTTPS:

| | **2а — свой домен** | **2б — автоподъём cloudflared** |
| --- | --- | --- |
| Как | nginx на своём сервере + труба до Windows (ssh -R или WireGuard), TLS на своём сервере | плагин сам запускает `cloudflared` quick tunnel и подставляет адрес |
| Кто видит трафик в открытом виде | только твой сервер | edge Cloudflare (включая содержимое) |
| Адрес | постоянный, старые кнопки в чате живут | меняется при перезапуске |
| Что нужно от тебя | сервер, сертификат, туннель до loopback-порта | ничего (кроме согласия на закачку бинарника) |

Вариант **2а** предпочтителен для постоянной работы. Проверено: `cloudflared` и
`tailscale` на этой машине не установлены.

## 6. Безопасность

- **Слой 1**: единственный фактор — контрольный токен. Сравнение за постоянное время
  (по SHA-256-дайджестам), на диск попадает только дайджест. 5 неверных попыток →
  пауза 15 минут; ответы неавторизованным — не чаще раза в 30 секунд. Только приватные
  чаты: из группы — игнор и разовая подсказка. Промпты принимаются только от
  привязанного чата, остальным — тишина и запись в лог. Секреты не логируются.
- **Слой 2** (когда включится): второй фактор — подпись Telegram
  `HMAC_SHA256(HMAC_SHA256(bot_token, "WebAppData"), data_check_string) === hash` плюс
  свежесть `auth_date`; контрольный токен проверяется отдельно; страница ничего не
  хранит в localStorage, токен сессии живёт в памяти и имеет TTL.
- Файл состояния — `0600`, атомарная запись (временный файл рядом + `rename`).
- Секреты не попадают в пакет: `cordis.patch.yml` бандла вставляет строку без `config`.

## 7. Установка и удаление

```bash
# установка (link — правки кода подхватываются без переустановки)
dsh plugin --profile web add link:W:\harness\dsh-telegram-app

# проверка (только для слоя 2, когда включён публичный адрес)
curl -s http://127.0.0.1:3080/tg-app/api/health

# удаление
dsh plugin --profile web remove dsh-telegram-app
```
